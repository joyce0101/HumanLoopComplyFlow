# LoopLedger 功能速览

面向团队成员和演示人员，说明当前已实现的功能、触发规则和使用边界。

## 1. 整个系统做什么

**抽取贷款申请 → AI 预判与风险分流 → 自动决定或人工审核 → 保存记录 → 监督指标与证据报告。**

当前申请来自 German Credit 测试集；系统记录审批决定，不执行实际放款，也尚未提供申请人自行填表的入口。

| 模块 | 已实现功能 | 主要文件 |
| --- | --- | --- |
| 模型与风险分流 | 贷款批准/拒绝建议、置信度、前五项特征贡献；按规则决定是否转人工；提供金标准控制题 | [model.py](../loopledger/model.py)、[gate.py](../loopledger/gate.py)、[gold.py](../loopledger/gold.py) |
| 数据持久化与监督指标 | 保存案件和审计事件；比较 AI 与人工决定；计算审核行为指标和告警；校验哈希链 | [ledger.py](../loopledger/ledger.py)、[metrics.py](../loopledger/metrics.py) |
| 页面与人工审批 | 批量运行、数据库待审队列、批准/拒绝/修改或暂缓、必填审核人和理由、记录耗时、展示指标 | [app.py](../app.py)、[pages/](../pages/) |
| 证据与报告 | 汇总案件数量、审核员指标、事件数量、链校验结果及法规映射，导出 Markdown / JSON | [evidence.py](../loopledger/evidence.py)、[报告模板](../templates/evidence_report.md.j2) |

## 2. 哪些申请需要人工审核

风险闸门遇到下列任意情况，会要求人工审核：

| 条件 | 当前规则 |
| --- | --- |
| AI 不够确定 | 置信度低于 `0.70` |
| 金额较大 | 贷款金额大于 `15,000`，单位沿用数据集 |
| 身份未确认 | `identity_verified` 没有明确设为 `True` |
| 控制题或异常输入 | 金标准题；或置信度、金额、决策、案例编号等检查异常 |

闸门全部通过时，按 AI 建议记录**自动批准或自动拒绝**。页面的“假设身份已验证”只是演示设置，不会实际核验身份。

预测或写入失败会显示错误；已经保存预测但未能保存分流时，案件保留待审，不会伪装为自动处理成功。每次点击 Run batch 都新增一批，队列显示数据库中的累计待审数。

## 3. 人工审核可以做什么

- **Approve application**：批准申请，可以与 AI 建议相同或不同。
- **Reject application**：拒绝申请，可以与 AI 建议相同或不同。
- **Modify / hold**：记录调整、暂缓或补充证据意见，并结束当前审核任务；不会自动批准贷款。

审核员姓名与理由必填，系统记录从打开本次案件到提交的耗时，包含中途离开页面的时间。成功提交后案件退出待审队列；重复提交同一案件会被拒绝。

目前没有材料上传、补件后重新入队或多轮审批版本流程。Modify / hold 的完整补件闭环仍待扩展。

## 4. 监督面板的四种颜色

颜色针对**同一审核员在当前数据库中的累计审核记录**，不是对某一笔贷款的批准颜色，也没有“最近一个月”等时间窗口。

**判断顺序：先灰色，再红色，再黄色，否则绿色。** 同一颜色中的条件满足任意一项即可。

| 颜色 / 页面状态 | 什么时候出现 | 应如何理解 |
| --- | --- | --- |
| ⚪ 灰色 · Insufficient data | 审核少于 **5 次**；或有审核缺少有效耗时；或找不到当时的原始 AI 决策 | 数据不足，暂不分配红黄绿 |
| 🔴 红色 · Review signals | 平均审核耗时 **< 5 秒**；或短理由比例 **≥ 80%**；或已审错误探针 **≥ 3 道**且检出率 **< 50%** | 建议优先复核这些行为信号 |
| 🟡 黄色 · Watch | 未触发红色时，以下任一项：平均耗时 **< 15 秒**；短理由比例 **≥ 40%**；至少 **5 次**可比较审核的推翻率为 **0**；已审错误探针 **≥ 3 道**且检出率 **< 80%** | 建议关注并结合具体案件检查 |
| 🟢 绿色 · No heuristic alert | 基础数据充分，且未触发上述红黄条件 | 当前没有规则告警，不代表已证明审核有效 |

例如：只审核 3 次，即使平均 2 秒也先显示灰色；达到 6 次、信息完整且平均 2 秒时会显示红色。尚无任何审核时，页面显示无审核记录，不会生成一行绿色结果。

四项主要指标的计算方式：

| 指标 | 含义 |
| --- | --- |
| 平均审核时长 | 有效审核耗时的平均数；“秒批”规则看平均值，不是只看某一次 |
| 推翻率 | 人工操作不同于 AI 建议的比例；`modify` 也计为推翻。推翻不等于人工错误，全批准也不等于零推翻 |
| 短理由比例 | 理由去除首尾空白后，少于 **12 个字符**的比例；恰好 12 个不算短 |
| 金标准错误检出率 | 已审核、已知 AI 出错的探针中，人工操作与预设正确答案相同的比例；正确 AI 控制题不计入分母 |

没有错误探针测量时，检出率显示为空或 `—`，不是 0%；普通批量申请不自带标准答案。告警还提供样本数和原因代码，便于定位触发条件。

这些经验规则用于提示审核主管或质控人员进一步检查，不自动认定违规、不自动撤销审批。系统目前没有自动指派复核人、异常工单或通知流程。

**另一种红绿颜色：** 审核页特征贡献图中的红色表示推动模型倾向拒绝，绿色表示推动批准，与上表的监督告警含义不同。条形值是逻辑回归的 log-odds 贡献，不是概率、因果结论或 SHAP 值。

## 5. 保存什么，报告能证明什么

| 数据 | 保存内容 |
| --- | --- |
| `cases` | 每个案件的原始 AI 预测和当前状态：自动处理 `auto`、待审 `pending`、已审 `reviewed` |
| `events` | 预测、分流及成功提交的审核事件，包括时间、审核人、操作、理由、耗时和哈希链字段 |
| `sqlite_sequence` | SQLite 自动维护的事件自增编号，无需人工填写 |

四个业务页面通过同一数据库接口读写。默认文件是根目录 `loopledger.db`；设置了 `LOOPLEDGER_DB_PATH` 时使用指定文件，刷新浏览器不会清空已落库记录。

Compliance 可校验事件链、预览报告并下载 Markdown / JSON。链校验检查本地事件一致性，不代表整库不可篡改、历史绝对完整或已获得合规认证；空事件链也可能校验通过。导出由用户点击触发。

记录覆盖已实现的业务事件，不包含每次鼠标点击、每次输入修改或尚未实现的多轮补件历史。

## 6. 最短测试路径

环境准备好后，在项目根目录运行 `python -m streamlit run app.py`，打开终端显示的网址。

1. **Run Batch**：选 10 条，先不勾选身份已验证，点击 Run batch；检查 Failed 为 0，申请进入待审队列。
2. **Review Queue**：填写同一审核员姓名和理由，尝试批准、拒绝；提交后待审数应减少。
3. **Oversight Dashboard**：刷新查看持久化指标；同一审核员不足 5 次时显示灰色属于正常情况。
4. **Compliance**：点击 Verify chain，再 Generate report，尝试两个下载按钮。

详细指标口径见 [监督指标说明](./OVERSIGHT_METRICS.md)，独立验收与篡改演示见 [功能验收说明](./BACKEND_DEMO.md)。
