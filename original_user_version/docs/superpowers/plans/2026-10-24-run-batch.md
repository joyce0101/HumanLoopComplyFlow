# Run Batch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement the C-owned batch page with count selection, explicit execution, routing results, and honest handling of unfinished persistence.

**Architecture:** Keep the page and small frontend adapters in `pages/1_Run_Batch.py`. Mock batches use shared `Prediction` / `GateResult` contracts and add pending cases to the existing review page's session queue. Model preview adapts A's current `load_data`, `predict(application, model_path=...)`, and `evaluate_risk` functions without modifying A/B modules. Preview results never enter the mock review queue or the database.

**Tech Stack:** Streamlit, pandas; scikit-learn only when model preview is selected. pytest/AppTest verify UI and actual trained-model integration using a temporary artifact.

**Spec:** `C_前端开发执行建议.md` section 4 and `PLAN.md` section 3, reconciled with current A/B source.

## Global Constraints

- Only implement the requested page, its tests, and this plan. Preserve user edits and the existing database.
- Default mock mode; model preview is explicit, never an automatic fallback.
- Count selection 1–200, default 50; no work on page load, slider changes, or ordinary reruns.
- Mock routing: confidence < 0.70 or amount > 15000. Demonstrative values, no claim of actual model output.
- Four mock patterns exercise auto approval, auto rejection, low confidence, and high amount.
- Each explicitly started batch receives unique IDs. Display per-batch counts, not system totals.
- Mock runs preserve existing pending/completed reviews and share the `rq_pending_reviews` / `rq_submitted_reviews` session contract.
- Model preview reproduces A's fixed holdout split, requires an already trained model, and does not train automatically.
- German Credit lacks identity-verification evidence. Preview defaults to unverified; any verified assumption requires an explicit demo checkbox.
- B currently provides only `init_db`; no page SQL and no claim that results were persisted.
- Do not change Review Queue, model, gate, ledger, schema, app entrypoint, or dependencies file. No commit/push.

## Review Focus

- Preview results mixed into mock queue or falsely presented as persisted.
- Ordinary reruns duplicating batches or deleting prior review state.
- Missing model/data or a failed prediction represented as a successful decision.
- Auto rejections counted as approvals or per-batch counts confused with cumulative totals.
- Fabricated identity verification, model explanations, or held-out sampling claims.

## Launch and limits

```bash
/tmp/synoptix-review-venv/bin/python -m streamlit run app.py
```

Use sidebar navigation to preserve the same session between Run Batch and Review Queue. A separate browser tab, the standalone review server, or a browser reload may use a different/reset session.
